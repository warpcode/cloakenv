## 2026-10-31 - Environment Variable Key CRLF Injection in Subprocess Execution
**Vulnerability:** `runner.validateCommand` enforced null-byte checks on environment entries and arguments, but did not reject newline (`\n`) or carriage return (`\r`) characters within environment variable keys or the command executable name. An environment key containing a newline (e.g. `INJECTED\nLD_PRELOAD=/evil.so=val`) could be passed to `syscall.Exec`, permitting downstream environment variable injection when child shells, tools, or `/proc/self/environ` parsers split environment definitions on newline boundaries.
**Learning:** Process wrappers injecting secrets directly via `syscall.Exec` or `exec.Command` must validate environment variable keys against CRLF characters in addition to null bytes; while multiline secret values are legitimate (e.g., PEM certificates, SSH keys), newlines in variable *identifiers* are structurally invalid in POSIX and represent an injection boundary vulnerability.
**Prevention:** Always validate that `commandName` and environment variable keys reject `\r` and `\n` in `validateCommand`, and format any rejected identifiers using `%q` to safely escape control characters in error output without exposing resolved secret values.
