# Commit message instructions

Conventional Commits, matching the convention used in this repository.

`type(scope): imperative summary`

- `type` is required. One of: `feat`, `fix`, `test`, `docs`, `refactor`, `perf`,
  `chore`, `ci`, `build`.
- `scope` is optional; include it only when the change is confined to one area.
  Scopes in use: `engine`, `provider`, `cmd`, `utils`, `runner`, `ci`, `deps`,
  `agents`, `AGENTS`, `lint`.
- Summary starts lowercase, imperative ("add", not "added" or "Adds"), no trailing
  full stop, one line of roughly 60-72 characters.
- Do not add a `(#123)` suffix — GitHub appends it on squash-merge.
- Do not use emoji or tag prefixes (`🧪`, `🔒`, `⚡`, `🧹`, `🛡️`, `Sentinel:`,
  `Security Fix:`). Those are historical, not current.
- Do not narrate the implementation. State what changed and why it matters.
- Do not write a summary that only restates the type, e.g. `test: add tests`.

Add a body only when the *why* is not obvious from the summary — a regression
fixed, a constraint found, a trade-off accepted. Short bullets, wrapped ~72 cols.

Example of the target form:
`fix(utils): reject URIs containing null bytes in ParseURI`
